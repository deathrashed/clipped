# Production Verification Audit

**Date:** 2026-05-31
**Status:** ⚠️ CRITICAL FAILURES DETECTED

## Executive Summary

- **Working:** MP3 extraction via Netlify Background Functions (mostly), `clip-request` dispatch, polling mechanism.
- **Partially Working:** `clips.json` schema (contains broken local paths).
- **Broken:** MP4/Video generation (completely ignored by backend), Blob storage cleanup (memory leak), Showcase asset loading for recent tests.

---

## 1. Verify Every Render Path

*Note: Since the backend Netlify Functions (`clip-job-background.js`) are currently hardcoded to strictly execute `yt-dlp` and `ffmpeg` for MP3 extraction, video paths fail by default.*

### Test 1: Library Audio -> MP3
- **Payload:** `{ "url": "...", "start": 0, "end": 15, "format": "audio", "template": null, "platform": "default" }`
- **Backend Status Progression:** `pending` -> `done`
- **Output / Duration:** ~1-3MB / ~5-15s
- **Success/Failure:** **SUCCESS**

### Test 2: Library Audio -> MP4
- **Payload:** `{ "url": "...", "start": 0, "end": 15, "format": "video", "template": "reel", "platform": "vertical_full" }`
- **Backend Status Progression:** `pending` -> `done` (Lying state)
- **Success/Failure:** **FAIL (Silent)**. The background function completely ignores `format: "video"` and the `template` parameter. It blindly runs the `libmp3lame` audio extraction and returns an MP3 renamed as a video, or fails to render video entirely.

### Test 3: URL Source -> MP3
- **Payload:** `{ "url": "https://youtube.com/...", "start": 30, "end": 45, "format": "audio" }`
- **Backend Status Progression:** `pending` -> `error` (Intermittent)
- **Success/Failure:** **PARTIAL**. Works for some URLs, but frequently fails because Netlify AWS IPs trigger YouTube's "Sign in to confirm you're not a bot" `yt-dlp` block.

### Test 4: URL Source -> MP4
- **Payload:** `{ "url": "https://youtube.com/...", "format": "video", ... }`
- **Success/Failure:** **FAIL**. Video rendering logic via Remotion/FFmpeg templates is completely missing from `clip-job-background.js`.

## 2. Verify Netlify Functions

### `clip-request`
- **Expected Request:** `POST` with `{ url, start, end, format, template, platform }`
- **Expected Response:** `200 OK` with `{ jobId }`
- **Status:** **WORKING**. Correctly stores initial blob state and dispatches background job.

### `clip-job-background`
- **Expected Request:** Invoked internally with `{ jobId }`.
- **Status:** **BROKEN (for video)**.
  - **Hardcoded constraints:** The script hardcodes `tmpClip.mp3`, `--audio-format mp3`, and `-c:a libmp3lame`.
  - **Missing logic:** It does not invoke Python, `bin/clipped`, or Remotion. It only extracts audio.
  - **Timeout Risks:** The 15-minute background limit is safe for audio, but will be tested heavily once Remotion Chromium rendering is actually implemented here.

### `clip-status`
- **Expected Request:** `GET ?job={jobId}`
- **Expected Response:** `{ status: "pending|done|error:..." }`
- **Status:** **WORKING**.

### `clip-download`
- **Expected Request:** `GET ?job={jobId}`
- **Status:** **PARTIALLY WORKING**. Hardcodes the `Content-Type: audio/mpeg` and `filename="clip-....mp3"`. Will corrupt file downloads if a video `.mp4` blob is ever successfully generated.

## 3. Verify Blob Lifecycle

For completed jobs:
- **Confirm output exists:** Yes, `jobId:audio` and `jobId:status` are created.
- **Confirm download endpoint resolves:** Yes, streams correctly.
- **Confirm blob cleanup behavior:** **BROKEN**.
  - The recommendation to use `ttl: 3600` was written in the docs (`SHOWCASE_HANDOFF.md`), but it was **never implemented** in the actual `store.set` call inside `clip-job-background.js`.
  - **Impact:** Every render permanently leaks memory in your Netlify Blobs storage, which will eventually incur storage limits/costs.

---

## 4. Verify clips.json

Based on a static audit of `showcase/clips.json` and `showcase/public/clips.json`.

- **Schema:** Array of clip objects.
- **Required fields present:** `filepath`, `filename`, `kind`, `template`, `platform`, `artist`, `title`.
- **Optional fields present:** `clip_start`, `clip_end` (or `start`/`end`), `timestamp`, `engine`, `aspect`.
- **Broken Entries:** **YES**.
  - There is a severe path leakage in `showcase/clips.json` generated by the sync script.
  - Example: Lines containing `../../../../../../tmp/clipped_test/11_waveform_pulse_juggaknots.mp4`.
- **Missing Paths:** Any filepath pointing to a `/tmp/` directory on your local MacBook will result in a `404 Not Found` when deployed to Netlify.

- **All video cards load:** **FAIL**. The 10+ recent test renders pointing to `/tmp/clipped_test/...` will display as broken video players on the live site.
- **All audio cards load:** **WORKING**. The `_audio/...` relative paths resolve correctly.
- **All smoke tests load:** **WORKING**. The `tests/videos/ffmpeg/...` and `remotion/...` paths resolve correctly because `deploy_showcase.sh` explicitly copies them.

## 6. Recommendations & Next Steps

Before writing *any* more UI transitions, the following backend architecture tasks must be resolved:

1. **Halt Video Generation Claims:** The UI implies it can generate MP4 templates (Reel, Gallery Square, etc.) from the web. The backend currently only extracts MP3s. Either disable the `format: "video"` UI temporarily, or implement the heavy Python/Remotion bridge in the Netlify background function.
2. **Patch the Blob Memory Leak:** Immediately add `{ ttl: 3600 }` (or similar) to the `store.set` calls in `clip-job-background.js` and `clip-request.js` to ensure temporary `/tmp` blobs don't permanently consume your Netlify storage.
3. **Fix the Sync Script Pathing:** Update `sync_showcase.py` to filter out or ignore any absolute paths originating from `/tmp/`, or ensure those files are actually copied into `dist_showcase/_video/` and given relative paths during the build step.
4. **Dynamic Download Headers:** Update `clip-download.js` to dynamically read the mime-type (MP3 vs MP4) from the blob metadata rather than hardcoding `audio/mpeg`.
